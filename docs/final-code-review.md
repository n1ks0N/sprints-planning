# Финальное ревью, 8 ноября 2026

Проверены основные цепочки изменённой ветки: ROADMAP/BACKLOG, расчёт нагрузки, перенос и применение планирования, участники, история, фильтры, накопительная пагинация, RTK Query, виртуализация карточек и объединённая миграция. Ревью сопровождалось исправлениями и регрессионными проверками; это не гарантия отсутствия ошибок во всех возможных состояниях приложения.

## Исправленные замечания

1. **Устаревшая нагрузка при последовательных действиях.** Сдвиг всей задачи читал распределение из props карточки. После быстрого сдвига строки отложенный рендер мог ещё содержать старые значения. Теперь обработчик читает текущие allocations из RTK Query через уже существующий `getTaskAllocations`, как обработчики строки. Проверка сочетает копирование строки, её сдвиг и сдвиг всей задачи.
2. **Лишняя загрузка закешированных страниц.** В трёх накопительных списках `forceRefetch` сравнивал номер страницы с предыдущим аргументом запроса. Возврат к фильтру с уже загруженной страницей 1 и начальным аргументом 0 мог повторно загружать весь префикс. Теперь проверяется, нужна ли страница за пределами загруженного диапазона. Инвалидация тегов, явный refetch, обновление по фокусу и обновление всего загруженного префикса сохранены. Это касается задач, сотрудников и planning backlog.
3. **Мёртвый код BacklogPage.** Удалены старые реализации редактируемого текста, участника и сортируемой строки, неиспользуемые цвета статусов и подсчёт нагрузки, состояния и обработчики прежнего группового распределения. Рабочая карточка и распределение на странице планирования сохранены. Дублирующее описание props заменено типом из компонента, промежуточная обёртка карточки удалена. Убраны два неиспользуемых параметра карточки.
4. **Лишние вычисления и подписки.** Удалены неиспользуемая подписка App на список команд, обработчик переключения команды, устаревшие помощники чтения кеша, лишняя карта имён участников и другие неиспользуемые переменные и импорты. Неиспользуемые позиционные аргументы API callbacks обозначены префиксом `_`.
5. **Старые методы репозитория.** Удалены пять методов TaskRepository для порядка задач без workspace и один оставшийся тестовый стаб. В рабочем коде вызовов не было. Сортировка использует методы с ограничениями по команде и workspace.
6. **Недостижимые защитные ветки.** В двух RTK Query `merge` удалены проверки отсутствия успешного ответа и существующего кеша: callback вызывается для успешных данных при существующей записи. Условие замены списка использует `first`, явно установленный в `queryFn`, вместо повторной проверки формы аргументов и приведения к `any`. Убраны избыточные null-проверки длины массива и типизированного patch.
7. **Проверки и справка.** Тест рендеров теперь отдельно завершает промежуточный выбор двух кварталов и измеряет работу для итогового выбора. Он проверяет отсутствие повторных запросов каждой страницы при перестановке кварталов; догрузка следующей страницы разрешена. В справке страницы сотрудников исправлено устаревшее утверждение об отсутствии пагинации.

## Сохранённые решения

- Независимые fetch-запросы коллекций задач предотвращают перемножение строк. Это ограниченный набор запросов на пакет, а не запросы на каждую задачу или ячейку.
- Блокировки исходных задач перед заготовками, проверка revision и проверка активности новых назначений защищают реальные сценарии гонок и изменения участников. Существующие неактивные участники сохраняются в задачах.
- Отдельная загрузка лидера нужна, когда он не входит в исполнителей. Удаление этой ветки ломает чтение его полей после завершения транзакции.
- Виртуализация использует стандартную библиотеку; React.memo, стабильные обработчики и локальное состояние редакторов подтверждены проверками соседних ячеек. Новых систем кеширования или зависимостей в этом ревью не добавлено.
- SQL в этом ревью не менялся. Проверки миграции для дубликатов, статусов, структуры индексов, частичного применения и прерванного concurrent DROP достижимы и покрыты интеграционными сценариями. Подробности — [безопасность объединённой миграции](migration-merge-safety.md).
- Версии Java, Spring Boot и ORTools не менялись. Компиляция использует существующий `release 17`; тесты выполнены на Temurin 21, не на SberJDK.

Пропущен старый `PlanningWorkbenchSchemaIntegrationTest`, требующий `PLANNING_SCHEMA_TEST_URL` и заранее подготовленной схемы. Новые `BackendSchemaAuditIntegrationTest` и все 10 сценариев `MigrationMergeSafetyTest` выполнены успешно. Они проверяют работу в отдельной схеме, отображение лидера вне исполнителей, JSON dirty checking, историю, очистку команды и безопасность миграции.

Браузерные проверки охватывают фильтры и ручные даты, создание и дублирование задач, неактивных участников, перенос в планирование и его применение, сохранение и откат правок нагрузки, кеширование, обновление загруженных страниц, историю и Excel. Проверки рендеров подтверждают один рендер видимых карточек для завершённого выбора квартала и отсутствие обновлений соседних ячеек при правке нагрузки.

После исправлений подтверждённых блокирующих замечаний в проверенных цепочках не осталось.

Тесты Java выполнялись в изолированной PostgreSQL с временными схемами. Браузерные сценарии с реальным API запускались отдельно от проверки неизменности public-схемы: их параллельные записи в тестовую БД мешали сравнению количества строк. Основная пользовательская БД тестами не изменялась.

В production-сборке сохраняется предупреждение о vendor-чанке около 502 KiB. Дополнительное дробление зависимостей не включено в это ревью. Новый замер производительности всех API не проводился: результаты предыдущего нагрузочного прогона 50 участников / 500 задач находятся в [аудите бэкенда](backend-performance-audit.md). В этом ревью проверены корректность и устранённые повторные запросы и рендеры.
