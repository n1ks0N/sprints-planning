# Sprints Planning Platform

Этот репозиторий содержит фронтенд (React + RTK Query) и Spring Boot-бэкенд для планирования спринтов. Теперь инфраструктура поддерживает запуск бэкенда и базы данных в Docker.

## Запуск PostgreSQL и бэкенда в Docker

1. Убедитесь, что установлены Docker и Docker Compose (v2).
2. В корне проекта выполните:
   ```bash
   docker compose up --build
   ```
   Команда соберёт образ бэкенда, запустит контейнеры `backend` (порт `8080`) и `db` (порт `5432`). Liquibase автоматически применит миграции при старте.
3. Для остановки и удаления контейнеров используйте:
   ```bash
   docker compose down
   ```
   Чтобы сохранить данные PostgreSQL между запусками, в `docker-compose.yml` используется именованный volume `db-data`.

### Переменные окружения

По умолчанию `docker-compose.yml` создаёт базу `sprints` и пользователя `sprints/sprints`. При необходимости переопределите переменные окружения в файле или через `docker compose --env-file`.

### Особенности миграций в Docker-профиле

Запуск через `docker compose up` активирует профиль `docker` для бэкенда. Liquibase работает стандартно и использует тот же changelog, что и в остальных окружениях. Для исправления ошибки checksum в changeset `1.0.0_3_team_support.sql` добавлен `validCheckSum` со старым значением, поэтому пересоздавать схему или вручную сбрасывать checksums не требуется. В боевых профилях (prod/stage) миграции применяются без дропа схемы; изменять задним числом уже применённые миграции по-прежнему нельзя.

## Запуск фронтенда (локально)

Бэкенд слушает префикс `/api/v1/sprints-planning`. Для фронтенда есть три основных сценария (`package.json`):

1. Локальный фронт + локальный бэкенд (DevServer проксирует на `http://localhost:8080/api/v1/sprints-planning`):
   ```bash
   npm install
   npm run dev:local
   ```

2. Локальный фронт + удалённый Java-бэкенд. Перед запуском укажите домен в `API_URL` (например, `API_URL=https://isu.sber.com/isu/isu_backend_common/sprints-planning`):
   ```bash
   API_URL=https://<ваш-домен> npm run dev:remote
   ```

3. Сборка фронтенда под заданный домен (используется то же значение `API_URL`, что и в предыдущем пункте):
   ```bash
   API_URL=https://<ваш-домен> npm run build:remote
   ```

Если `API_URL` задан относительным путём, DevServer автоматически проксирует запросы на локальный сервер; для абсолютных URL запросы уходят напрямую на указанный домен.

### Управление командами

В интерфейсе доступна страница `/#/teams` для управления списком команд: можно добавлять новые, переименовывать и удалять. При удалении команда спрашивает, нужно ли удалять все связанные данные. Если данные не удалять, команду можно удалить только при отсутствии ссылок на неё в таблицах.

## Полезные команды

- Проверка состояния контейнеров: `docker compose ps`
- Просмотр логов: `docker compose logs -f backend` или `docker compose logs -f db`
- Повторная сборка только бэкенда: `docker compose build backend`

## Разработка без Docker

Если нужно запускать сервис локально без контейнеров, используйте инструкции из `src/README.md` для фронтенда и `server/` для бэкенда (Maven + PostgreSQL).
